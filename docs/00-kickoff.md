# Hackathon kickoff checklist

## First 30 minutes
- [ ] Read the exact challenge statement and event rules.
- [ ] Identify target user, pain point and desired outcome.
- [ ] Record judging criteria, submission deadline and prohibited tools/data.
- [ ] Check API, dataset, model, device and permission feasibility.
- [ ] Agree one demo-critical user journey.
- [ ] Define Must / Should / Could / Won't scope.
- [ ] Assign a single accountable owner to each task.
- [ ] Choose a communication channel and one source of truth for tasks.
- [ ] Create the repository board, issues and initial integration checkpoint.

## Before parallel coding
- [ ] Agree frontend routes and UI states.
- [ ] Agree API request/response and error contracts.
- [ ] Agree data ownership and schema/migration approach.
- [ ] Agree local run/test commands.
- [ ] Create a thin vertical slice issue.
- [ ] Confirm how the deployed demo will be accessed.

## Timeline guardrails
- 25% of event time: problem and MVP are locked.
- First third: runnable skeleton and first integration path exist.
- Around 60%: stop expanding scope; complete the main journey.
- Final 15–20%: integration, testing, deployment, demo rehearsal and submission.
- Event rules and actual deadlines always override this generic schedule.
